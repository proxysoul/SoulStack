# First-draft mistakes and the rules that fix them

Every rule in the skill exists because a first draft got it wrong. Check your work against this list before showing it.

| First-draft mistake | Rule |
| --- | --- |
| A restyle of the old site, or a template look | One core idea taken from the product, one art direction per theme, something new |
| Only tested on a laptop | Check at 390, 1440 and 3440 wide |
| Everything too big | Start about 30% smaller than instinct |
| The background drowns the text | Movement at the edges, quiet behind text |
| Slow | Measure before and after; lazy-load heavy parts |
| Too much text | Visuals plus one short line |
| Boxes overflow, things overlap | Layout checks at every width must report nothing |
| A mascot chasing the cursor, no way to stop motion | No cursor chasers; a pause button always in the top bar |
| Gimmicky shapes per theme | Per-theme style without decoration for its own sake |
| Screenshots pasted on a colour that doesn't match | Capture transparent or on a green screen and key it out |
| Then toned down so far it lost its life | Keep product imagery and a little motion on the pages that sell |
| The download page doesn't show what you get | Real app screenshots there too |
| Testimonials dropped or made up | Keep every real quote, verbatim, with a picture |
| A theme switch or picker that blurs | A brand-shaped transition, dim only, opens in one step |
| One still screenshot per app | Several real views per app, every theme and mode |
| Charts nobody can read | Logos next to names, simple bars, real units, no log scales |
| "Coming soon" sections, cramped cards | No placeholders; labels never touch values |
| The next agent has to relearn everything | Write the `design_system/` folder with tools inside |
| Small brand type misreads | Check the logo and wordmark at large magnification |
| Content collides with the top bar on wide screens | One clearance token under the bar, growing with the screen |
